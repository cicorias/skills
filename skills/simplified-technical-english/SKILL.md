# Simplified Technical English (STE) Writer & Editor

## Purpose
Help the user write and edit technical documentation in **Simplified Technical English** — the controlled-language approach defined by the ASD-STE100 specification. STE makes technical text easy to understand, especially for non-native English readers and for machine translation.

Apply this skill when asked to **write** procedures/descriptions/warnings, **rewrite/simplify** technical text, or **review/audit** text against STE.

> Scope: This skill teaches STE *principles and method*. It is not the ASD-STE100 dictionary. The official specification (published by ASD, asd-ste100.org) defines the authoritative approved words, parts of speech, and meanings. For certified compliance, defer to the current issue of the specification and a checker tool. Treat this as a faithful working method, not the certified word list.

## Core philosophy
1. **One word, one meaning** — never use a word two ways.
2. **One meaning, one word** — pick one term per concept and repeat it; do not rotate synonyms.
3. **Small, controlled vocabulary** — prefer short, common, unambiguous words.
4. **Short, direct sentences** — say one thing clearly; split complex ideas.
5. **Say it explicitly** — keep grammar complete; never drop words to shorten.

## Vocabulary
- Use the plainest word that carries the meaning. Replace formal/Latinate words.
- Use each word as one part of speech and one meaning.
- No synonyms, jargon, slang, or idioms. Keep and standardize real technical names and technical verbs.
- Be specific: *bolt* not *thing*; *within 3 seconds* not *quickly*.

Illustrative substitutions (direction, not the official dictionary): commence/initiate → **start**; terminate → **stop**; utilize → **use**; prior to → **before**; subsequent to → **after**; in order to → **to**; assist → **help**; ensure → **make sure**; obtain → **get**; sufficient → **enough**; approximately → **about**; attempt → **try**; locate → **find**; advise/notify → **tell**; in the event that → **if**.

## Verbs
- Active voice (always in procedures; as much as possible in descriptions).
- Imperative for instructions: *Remove the panel.*
- Simple tenses only (present, past, future). Avoid perfect and progressive tenses.
- Avoid "-ing" gerund/participle chains — split into separate steps or clauses.
- One action verb per instruction (two only if the actions happen together).

## Sentences
- Procedural sentences ≤ ~20 words; descriptive ≤ ~25 words.
- One instruction per sentence in procedures.
- Put the condition first: *If the light is on, close the valve.*
- Natural word order; keep related words together.
- Do not omit articles or connecting words to save space.

## Noun phrases
- Noun clusters ≤ 3 words. Break longer ones with prepositions and articles.
  - *aircraft fuel system pressure relief valve access panel* →
    *the access panel for the pressure-relief valve in the aircraft fuel system*
- Keep articles (*the pump*, not *pump*).

## Procedures
- Imperative, numbered steps; one action per step.
- Use vertical lists for sequences and sets of conditions.
- Keep steps in the order performed; don't reference "the step above/below."
- State conditions and results plainly: *If X, do Y.* / *Result: the indicator comes on.*
- Don't mix a warning, a description, and an instruction in one step.

## Warnings, cautions, notes
- Put the warning/caution **before** the step it applies to.
- Start with a simple command, then give the reason/consequence.
- Hierarchy: **WARNING** (people), **CAUTION** (equipment), **NOTE** (info).
- Example: *WARNING: Do not touch the surface. The surface can be very hot. If you touch it, you can get burns. Wait until the surface is cool.*

## Descriptive writing
- One topic per paragraph; ≤ ~6 sentences.
- Topic sentence first; use connecting words (*first, then, also, but, because*).
- Passive allowed sparingly when the actor is unknown/unimportant; active preferred.

## Punctuation & formatting
- Simple punctuation; avoid semicolons/dashes that join two ideas — split instead.
- Hyphenate compound modifiers (*pressure-relief valve*).
- Prefer lists, tables, and short paragraphs. Define abbreviations once; keep units consistent.

## Output modes
- **Write:** produce STE-style text directly (numbered steps, front-loaded warnings, short active sentences).
- **Rewrite/simplify:** return the cleaned text, then a short bullet list of key changes and why.
- **Review/audit:** list each issue as *offending text → rule broken → fix*, then give the corrected version.
- Always keep terms consistent (ask which to standardize on if the source uses several), and flag — never silently drop — safety information.

## Self-check before output
- Active voice; imperative for instructions.
- Procedural ≤ ~20 words; descriptive ≤ ~25 words.
- One instruction per step; one topic per paragraph (≤ ~6 sentences).
- Plain, consistent words; no synonyms/jargon/idioms/"-ing" chains.
- Noun clusters ≤ 3 words; articles kept.
- Warnings/cautions before the step, command + reason.
- No words dropped to shorten; meaning explicit.
